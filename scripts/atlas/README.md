# 计算机知识图谱

公开入口 `/apps/cs-atlas/`，无需登录，默认知识点依赖。`layout=tree` / `columns` 保留分类浏览，点击具体知识点进入同页局部依赖图；`layout=route` 为另行维护的模块规划。

## 点级关系

- `point-catalog.json`：原树的稳定 ID、名称、完整路径及父子关系；知识树顺序改变时须更新 catalog。
- `point-rules.json`：2,255 个单独指定关系的条目（全部 1,959 个 depth3 条目，加 296 个深层条目），39 个纯分类节点及核查资料。分类节点不作为先修。
- `compile-points.mjs`：生成 `point-data.json`。其余 4,851 个细项以最近的非分类父概念的**基本含义**为上下文前提，不复制所属模块依赖，也不要求学完父主题所有子项。这是概念衔接，不能宣称均已逐一人工穷尽跨主题背景。
- `point-view.js` / `point-view.css`：目录、局部依赖图、逐级回溯、拓扑顺序、任选和建议补充。跨方向原地更新，可返回上一个知识点。`point` URL 参数保存具体条目。

关系用 `requires: [{id, depth, reason}]`，任选用 `anyOf`；`recommended` 不参与硬性顺序。`scope: 基本含义` 限制父概念的学习范围。编译检查全覆盖、有效引用和全局无环（含所有任选候选边），拒绝缺项和循环。顺序是一种符合依赖的安排，互不依赖的点可并行。

当前共 7,106 个知识条目与 39 个分类条目、8,106 条候选前置边。修改后以编译统计为准。

## 模块与构建

`learning-routes.json` 维护 27 个方向、352 个模块的入口、过渡、顺序与验收；`module-registry.json` 保存映射；`learning.js` 渲染模块规划。点级图不再展示继承的模块面板。`source-audit.json` 保存模块资料来源。

运行 `npm run check`、`npm test`、`SITE_BASE_PATH= SITE_URL=https://iwxt.cn npm run build`。先验证模块、编译点级关系，再生成哈希资源并构建博客。保留已发布资源避免旧缓存失效，不提交中间开发产物。

程度：认识（辨认术语）、理解（说明关系与条件）、会用（独立完成小例子）、能实现（写出核心过程并验证）。这不是个人掌握记录。资料支持概念和课程背景；关系与顺序是本项目的教学安排，不得声称官方认证或保证零知识缺漏。
